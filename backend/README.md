# Auto Parts API — بکند فروشگاه قطعات یدکی

NestJS 11 + Prisma 5 + PostgreSQL. چندفروشگاهی (multi-tenant)، احراز هویت JWT، نقش‌ها.

## اجرا

```bash
docker compose up -d                 # PostgreSQL (یا از پایگاه‌داده‌ی خودتان استفاده کنید)
cp .env.example .env                 # DATABASE_URL، JWT_SECRET، JWT_REFRESH_SECRET و ENCRYPTION_KEY را تنظیم کنید
npm install
npx prisma migrate dev --name init   # ساخت جدول‌ها (اگر قبلاً migrate کرده‌اید، یک migration جدید می‌سازد)
npm run prisma:seed                  # اطلاعات پایه + فروشگاه نمونه (SEED_DEMO=false فقط اطلاعات پایه)
npm run start:dev
```

- API: `http://localhost:3000/api/v1` — Swagger: `http://localhost:3000/api/docs`
- ورود نمونه: `09120000000` / `demo1234` (مدیر) و `09121111111` / `demo1234` (فروشنده)
- `CORS_ORIGINS` باید شامل آدرس فرانت باشد؛ `FRONTEND_URL` و `APP_PUBLIC_URL` برای بازگشت از درگاه پرداخت لازم‌اند.
- `ENCRYPTION_KEY` (`openssl rand -hex 32`): کلید رمزنگاری اطلاعات حساس (کلید خصوصی مودیان، کلید API پیامک، مرچنت‌کد). **گم نکنید.**

## تست

```bash
npm test             # تست واحد (۳۵ تست): فاکتور، برگشتی، شناسه/امضا/رمزنگاری مودیان، سرویس مودیان با سازمان جعلی، پیامک، درگاه
npm run test:e2e     # تست دودی سیم‌کشی ماژول‌ها، نقش‌ها و ایزوله‌سازی فروشگاه (با پایگاه‌داده‌ی جعلی؛ اگر E2E_DATABASE_URL تنظیم باشد، تست ایزوله‌سازی با Postgres واقعی و RLS هم اجرا می‌شود)
```

## نسخه‌ی اول
**امنیت:** شناسه فروشگاه فقط از توکن خوانده می‌شود (نه هدر `x-tenant-id`)؛ `JWT_SECRET` الزامی و بدون پیش‌فرض؛ Rate limit فعال؛ `sortBy` فقط از فهرست مجاز.
**اصلاح منطق:** تخفیف ردیفی و مالیات، کسر موجودی با شرط «موجودی کافی» داخل تراکنش، بهای تمام‌شده‌ی فروش، لغو فاکتور به همان انبار، وصول چک، آزادسازی SKU در حذف نرم.
**ماژول‌ها:** خرید، دریافت/پرداخت، گزارش‌ها، برند، دسته، واحد، انبار، خودرو، کاربران، تنظیمات فروشگاه، انتقال بین انبارها، انبارگردانی، صورت‌حساب طرف‌حساب، سازگاری با خودرو، جایگزین، موجودی اولیه، AuditLog.

## نسخه‌ی دوم
برگشتی جزئی، پیش‌فاکتور و تبدیل به فاکتور، ورود/خروج گروهی کالا، هزینه‌ها و سود خالص، گزارش فعالیت.

## نسخه‌ی سوم
- **اتصال به سامانه مودیان** (نسخه ۱ API، کلید خصوصی): تولید شماره مالیاتی (Verhoeff)، امضا و رمزنگاری بسته، ارسال، استعلام، همگام‌سازی، پیش‌نمایش بسته با فهرست مشکلات. **راهنما و محدودیت‌ها: `docs/MOODIAN.md`.**
- **پیامک** (کاوه‌نگار، SMS.ir و حالت آزمایشی): پیامک فاکتور، یادآوری بدهی مشتریان، گزارش ارسال.
- **پرداخت آنلاین** (زرین‌پال، API نسخه ۴): لینک پرداخت برای هر فاکتور، صفحه‌ی عمومی پرداخت، تأیید تراکنش و ثبت خودکار دریافت (بدون ثبت تکراری).
- **برگشتی مستقل** از فاکتور اصلی. فیلد «شناسه کالا/خدمت» روی کالا.
- **امنیت:** گزارش فعالیت دیگر کلید خصوصی، کلید API، مرچنت‌کد، رمز و توکن را ذخیره نمی‌کند (با تست).

## قرارداد مبالغ
- واحد پول **ریال** (`settings.currency = RIAL`)؛ فقط اگر فروشگاهی صراحتاً `TOMAN` باشد، برای مودیان و درگاه ×۱۰ می‌شود.
- `currentBalance` مشتری: مثبت = بدهکار به ما. تأمین‌کننده: مثبت = ما بدهکاریم.

## محدودیت‌ها — لطفاً بخوانید
- **اتصال‌های خارجی با سرویس واقعی آزموده نشده‌اند.** مودیان، کاوه‌نگار، SMS.ir و زرین‌پال با شبیه‌ساز و بر پایه‌ی مستندات/کتابخانه‌های مرجع پیاده شده‌اند؛ هر کدام را ابتدا در محیط آزمایشی خودش امتحان کنید.
- مودیان: فقط نسخه ۱ API؛ بدون فاکتور اصلاحی/ابطالی و بدون ارسال خودکار (جزئیات در `docs/MOODIAN.md`).
- بکند روی PostgreSQL واقعی اجرا نشده؛ تایپ‌چک، تست واحد و تست دودی با پایگاه‌داده‌ی جعلی انجام شده است.
- پایان دوره‌ی آزمایشی (trial) اعمال نمی‌شود (ماژول صورت‌حساب اشتراک پیاده نشده است).


## موجودی به تفکیک قیمت خرید (InventoryLot)
- بعد از `prisma migrate dev` (ساخت جدول `inventory_lots`) یک‌بار `prisma/sql/004_inventory_lots_backfill.sql` را اجرا کنید تا موجودی فعلی به‌صورت یک ردیف قیمت ثبت شود؛ سپس `002_rls.sql` را دوباره اجرا کنید.
- روش بهای تمام‌شده در تنظیمات فروشگاه: `settings.costMethod` = `AVERAGE` (میانگین موزون) یا خالی (انتخاب قیمت هنگام فروش).
